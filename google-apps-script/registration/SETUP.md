# 구글 폼 자동 연결 — 설정 및 배포 안내

로컬에서 2027년 폼 생성·행사 옵션 연결과 문구 갱신을 확인했습니다. 홈페이지 배포 전 빌드와 테스트를 실행하고, 배포 후 공식 관리자 도메인에서 구글 로그인을 마지막으로 확인합니다.

## 사용자가 한 번 할 작업

1. 기존 Apps Script 프로젝트 **KSIS 신청 관리 연결**을 엽니다.
2. 로컬 `google-apps-script/registration/Code.gs`의 **전체 내용**을 복사합니다. Apps Script의 **Code.gs** 기존 내용을 전체 선택하고 교체한 뒤 저장합니다. `appsscript.json`과 기존 스크립트 속성은 수정하지 않습니다.
3. 상단 함수 목록에서 **setupRegistrationAutomation**을 선택하고 **실행**합니다. 기존 관리자로 로그인해야 하며, 결과는 `{ready:true}`입니다. 이 단계는 기존 2026년 폼을 재사용하도록 등록하며 새 폼은 생성하지 않습니다.
4. **배포 → 배포 관리 → 기존 API 실행 파일의 수정(연필) → 버전: 새 버전 → 배포** 순서로 업데이트합니다. 새 배포를 만들지 않고 기존 배포를 수정하므로 기존 배포 ID를 계속 사용합니다. 액세스는 기존 **나만**을 유지합니다.

클라이언트 비밀번호나 인증 코드는 복사하거나 전달할 필요가 없습니다. 현재 OAuth 범위도 그대로입니다.

## 이후 관리자가 사용하는 순서

1. Decap → 협회 일정 → 새 일정에서 제목·날짜·시간·장소 등 필수 내용을 입력합니다.
2. **신청 받기 · 저장 시 구글 폼 자동 연결**을 켭니다.
3. 저장/게시를 누르면 구글 로그인 후 행사 날짜의 연도를 기준으로 공용 폼을 찾습니다. 없으면 그 연도 폼을 생성합니다. 로컬 저장이어도 실제 구글 폼은 변경됩니다.
4. 폼의 행사 선택 옵션을 추가하고, 해당 행사가 미리 선택된 신청 링크를 일정에 저장합니다. 명단 버튼은 그 일정의 고유 식별자로 연결됩니다.
5. 구글 연결 실패 시 일정 저장을 중단합니다. 같은 일정 재시도는 같은 폼·행사 식별자를 재사용합니다.

## 보존 및 현재 범위

- 2026년에 2027년 행사를 등록하면 2027년 폼을 사용합니다. 1월 1일까지 기다리지 않습니다.
- 각 행사 설정을 개별 Script Property에 저장하여 하나의 JSON 속성에 모든 행사 정보를 몰아넣지 않습니다.
- 행사 선택지는 `날짜 | 분류 | "일정 제목"`으로 표시합니다. 분류는 정기 포럼·교육 특강·수익 실무·친목 소모임 중 일정에서 선택한 값을 사용합니다. 제목 변경 시 선택지는 갱신하고, 이전 문구는 별칭으로 보관해 기존 응답의 조회·취소를 유지합니다. 동일 날짜·제목을 다른 행사에 재사용하면 명단 혼합을 막기 위해 연결을 중단합니다.
- 연결된 행사의 연도 변경은 기존 응답이 섞이지 않도록 중단합니다. 이 경우는 별도 이전 작업이 필요합니다.
- 신청 받기를 끄고 저장하면 선택 옵션에서 제외합니다. 연도의 마지막 접수 행사가 닫히면 폼 접수를 닫습니다. 기존 응답은 보존합니다.
- 새 연도 폼의 소유자는 생성 시 로그인한 관리자입니다. 현재는 기존 소유자 계정만 자동 생성 관리자로 초기화합니다. 다른 직원들의 구글 접근 권한 설정은 별도 단계입니다.
- Google 폼 준비와 CMS 파일 저장은 하나의 원자적 작업이 아닙니다. 구글 준비 후 파일 저장이 실패하면 옵션이 남을 수 있으며, 동일 일정으로 재시도하면 중복 없이 이어갑니다.
- 실제 구글에서 2027년 폼 자동 생성과 행사 옵션 추가·갱신을 확인했으며, 테스트 일정은 삭제했습니다. 배포 후 공식 도메인에서 로그인과 명단 연결은 추가 확인이 필요합니다.

참조: https://developers.google.com/apps-script/api/how-tos/execute

## 홈페이지 배포

- 공식 관리자 주소는 https://www.rebornsenior.com/admin/ 입니다. Google OAuth의 승인된 JavaScript 원본에 https://www.rebornsenior.com 이 등록되어 있어야 합니다.
- 현재 API 실행 파일은 기존 소유자 계정만 사용할 수 있습니다. 다른 직원 계정은 별도로 Google 테스트 사용자·폼 접근 권한·Apps Script 접근 설정이 필요합니다.
- 관리자 명단 페이지는 registration-manager.html이며, 행사 식별자가 있어야 열립니다. 조회·삭제 권한은 Apps Script에서 다시 검사합니다.
- 시범 전용 페이지는 .codex-runtime/registration-prototypes에 보관하여 배포에서 제외했습니다.
- 홈페이지 기존 신청 링크는 신청 받기가 켜진 경우 자동 연결된 Google Forms 주소를 사용합니다. 기존 일정의 카페 링크와 레이아웃은 보존합니다.
- 일정 삭제 전에는 신청 받기를 끄고 저장해 Google 폼의 접수 옵션도 닫아야 합니다.

## 분류 표시 업데이트 적용 순서 (2026-10-16)

1. Apps Script의 Code.gs 내용을 이 폴더의 최신 Code.gs 전체 내용으로 교체하고 저장합니다. appsscript.json·속성·권한은 그대로 둡니다.
2. 함수 메뉴에서 updateExistingRegistrationLabels를 선택하고 실행합니다. 확인된 37회 행사와 바람이 전하는 노래의 선택지를 갱신합니다. 접수가 꺼진 행사는 건너뜁니다. 기존 응답은 별칭으로 유지하며 삭제하지 않습니다.
3. 배포 → 배포 관리 → 기존 API 실행 파일 연필 → 새 버전 → 배포합니다. 기존 배포 ID와 나만 권한을 유지합니다.
4. 홈페이지 변경을 커밋·푸시하고 배포 후 관리자 화면을 강력 새로고침합니다. 이후 일정 저장 시 선택한 분류가 자동 반영됩니다.
5. 실제 Google Forms에서 두 선택지의 날짜·분류·제목 표시를 확인합니다. 로컬 테스트 통과만으로 실제 반영이 확인된 것은 아닙니다.

홈페이지 푸시만으로 Google Apps Script는 업데이트되지 않습니다. 최신 API는 labelVersion:2를 반환하고, 관리자 저장 시 이 값으로 구버전 배포를 감지합니다.
